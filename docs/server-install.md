# התקנת השרת

הרצה אחת, ארבע שאלות, וזהו. הטרמינל נוגעים בו פעם אחת — בהתקנה;
כל השאר בקונסולה.

---

## איזו מכונה צריך

**לשלב א' בתוכנית הבדיקות — כל דבר.** מכונה וירטואלית, מחשב ישן, לפטופ שהתפנה. אין צורך לחכות לתקציב כדי להתחיל.

| | מינימום לבדיקות | לייצור |
|---|---|---|
| מעבד | 2 ליבות | 4+ ליבות |
| זיכרון | 4GB | 16GB |
| דיסק | 40GB | NVMe, 2–4TB לספריית האימג'ים |
| רשת | כרטיס אחד | שניים — אחד לחדר השיכפולים, אחד trunk למכללה |
| מערכת | Debian 13 | Debian 13 |

**הערה על המכונה הווירטואלית:** היא עובדת מצוין כשרת, אבל **הלקוח** שבודקים איתו חייב להיות מחשב פיזי עם UEFI ו-Secure Boot דלוק. VM עם Secure Boot מדומה לא יוכיח שהשרשרת עובדת על החומרה שלך.

**למה NVMe בייצור:** מופיע בנספח ב' כסיכון. כשמשדרים ל-30 מחשבים במקביל, דיסק השרת הופך לצוואר הבקבוק לפני הרשת.

**לפני שמתחילים:** קבעו לשרת כתובת IP סטטית על הכרטיס שישרת את
ההפצה. המתקין גוזר ממנה את כתובת המערכת.

---

## התקנה

```bash
sudo ./install/setup-boot-server.sh
```

המתקין שואל ארבע שאלות:

1. **איזה כרטיס רשת** — מתוך רשימה של מה שקיים במכונה, עם המצב
   והכתובת של כל אחד. לא מקלידים שמות.
2. **שם משתמש למנהל**
3. **סיסמה** (8 תווים לפחות)
4. **אישור סיסמה**

זהו. כתובת המערכת נגזרת מהכרטיס שנבחר. המתקין מתקין את החבילות
(dnsmasq, ‏shim ו-GRUB חתומים, FastAPI), מעתיק את הקוד ל-`/opt/imagectl`
(או מושך אותו מ-git כשהסקריפט רץ לבדו), פורס את שרשרת האתחול על
שורש ה-TFTP, יוצר את משתמש המנהל, ומרים את השרת כשירות systemd.

בסיום הקונסולה זמינה בכתובת שהודפסה, עם המשתמש שהגדרתם.

רוצים רק לראות מה יקרה? `sudo ./setup-boot-server.sh --dry-run`.
לאוטומציה יש דגלים שמדלגים על השאלות — `--help` מפרט.

**הסקריפט עובד גם לבדו**: קובץ ה-GRUB הקבוע מוטמע בו, וכשהריפו לא
לצידו הוא מושך את הקוד מ-GitHub. העתיקו אותו לשרת חדש והריצו.

## מה בכוונה *לא* קורה בהתקנה

**DHCP לא נדלק.** זו ההגדרה המסוכנת ביותר במערכת (אפיון סעיף 24) —
הדלקה בטעות על רשת המכללה משביתה אותה. לכן היא לא החלטה של רגע
ההתקנה: אחרי שהמערכת למעלה, נכנסים לקונסולה → לשונית **רשת**, ומדליקים
DHCP מלא או proxy על הכרטיס הנכון, מאחורי כל שכבות הבטיחות — כבוי
כברירת מחדל, הקלדת שם הכרטיס, זיהוי DHCP קיים, ואישור נוסף ל-trunk.
עד אז dnsmasq מגיש TFTP בלבד, ומחשבים לא יעלו ב-PXE.

היתרון: אפשר לשנות את ההחלטות בלי להתקין מחדש, וכל שרת עתידי
(או מי שמקים אותו) לא נדרש להחליט כלום מראש.

## שני תהליכי dnsmasq: ההפצה וה-proxy (#36)

מצב proxy **לא** רץ באותו תהליך dnsmasq שמחלק את כתובות וילן ההפצה.
הסיבה: ב-dnsmasq 2.91 לקוח UEFI ששולח בקשת PXE לפורט 4011 במצב proxy
מקפיא את התהליך — 100% מעבד, מפסיק לענות לכל הסוקטים, לא מעבד אפילו
SIGTERM. באינסטנס משותף זה אומר שמתג בקונסולה יכול להשבית את שירות
הכתובות של כל המכללה. ההפרדה לא מתקנת את הבאג; היא מוודאת שהתהליך
שנתקע הוא תהליך שאפשר לאבד.

| | האינסטנס הראשי | אינסטנס ה-proxy |
|---|---|---|
| יחידה | `dnsmasq` | `imagectl-proxy` |
| קובץ בסיס | `/etc/dnsmasq.d/imagectl.conf` (המתקין) | — |
| קובץ מהקונסולה | `/etc/dnsmasq.d/imagectl-dhcp.conf` | `/etc/imagectl/dnsmasq-proxy.conf` |
| מה הוא עושה | DHCP מלא + TFTP | תשובות PXE בלבד + TFTP לכרטיסים שלו |
| מתי רץ | תמיד | רק כשכרטיס במצב proxy |

מה שמאפשר לשניהם לחיות על אותה מכונה הוא `bind-interfaces` בשני
הקבצים: כל תהליך תופס את הפורטים של הכרטיסים שלו בלבד. בקובץ הראשי
כל כרטיס proxy מופיע כ-`except-interface`, ומפורשות **לא** כ-`interface`
— גם לא כדי להגיש TFTP, כי אז שני התהליכים היו נלחמים על פורט 69.

המתקין יוצר את `/etc/imagectl`, מעתיק את `imagectl-proxy.service`
ומשאיר את היחידה כבויה. הקונסולה היא שמריצה `systemctl restart` או
`stop` עליה לפי מצב הכרטיסים, ולכן היחידה אינה `enabled`: אחרי אתחול
היא לא עולה מעצמה, ומצב proxy נדלק ביודעין. יחידת השרת מוסיפה
`-/etc/imagectl` ל-`ReadWritePaths` (המקף = "התעלם אם אינו קיים", כדי
ששרת ותיק בלי התיקייה יעלה כרגיל).

**שדרוג שרת קיים** — שלושה צעדים, בלי התקנה מחדש:

```bash
sudo install -d -m 0755 /etc/imagectl
sudo install -m 0644 install/imagectl-proxy.service /etc/systemd/system/
sudo install -m 0644 install/imagectl-server.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl restart imagectl-server
```

**אזהרה שנשארת בתוקף:** גם מבודד, ה-proxy עצמו עדיין קופא ב-2.91 —
תחנה לא תסיים אתחול רשת דרכו. הקונסולה מציגה את זה ליד המתג. עד
שתיבדק גרסת dnsmasq חדשה יותר במעבדה (‏#36), מצב proxy הוא לניסויים.

## היחידה שמחזירה שינוי רשת שלא אושר (‏#56)

הגדרות הרשת של השרת עצמו נעשות מהקונסולה (לשונית **רשת** → "כתובת
השרת עצמו"). שינוי כתובת על הכרטיס שדרכו המנהל מחובר מנתק אותו — ואז
אין דרך לבטל. ההגנה היא החזרה אוטומטית תוך דקה, והיא **חייבת לשרוד גם
מוות של השרת**: שינוי שהפיל את הרשת מפיל לעיתים גם את השירות, ותהליכון
ב-uvicorn לא היה רץ בדיוק כשצריך אותו.

לכן זו יחידת systemd נפרדת, שאינה יודעת דבר על השרת:

```bash
sudo install -m 0644 install/imagectl-netrollback.service \
                     install/imagectl-netrollback.timer \
                     /etc/systemd/system/
sudo install -m 0644 install/imagectl-server.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now imagectl-netrollback.timer
sudo systemctl restart imagectl-server
```

| | |
|---|---|
| היחידה | `imagectl-netrollback.service` — ‏`python3 -m server.netcfg_rollback` |
| הטיימר | `imagectl-netrollback.timer` — ‏`OnBootSec=0`, ואז כל עשר שניות |
| הסמן | `/var/lib/imagectl/netcfg/pending.json` |
| ‏ReadWritePaths של היחידה | `/var/lib/imagectl /etc/network/interfaces.d /etc` |

**‏`--state-dir` חייב להתאים לשרת.** ברירת המחדל בשרת היא
`<data-dir>/netcfg`, וה-`data-dir` הוא `/var/lib/imagectl` — כלומר
`/var/lib/imagectl/netcfg`, בדיוק כמו ב-`ExecStart`. שני נתיבים שונים
פירושם שהסמן נכתב במקום אחד ונקרא באחר: זה נראה בדיוק כמו הגנה
שעובדת, וזו הגנה שלעולם לא תיפעל.

**היחידה של השרת צריכה גם היא הרשאות חדשות** —
`/etc/network/interfaces.d` ו-`/etc` (בשביל `resolv.conf`, שהוא קובץ
בשורש ואי אפשר לפתוח אותו לבדו). בלעדיהן הכתיבה נכשלת בגלוי והקונסולה
אומרת זאת; היא לא מתחזה להצלחה.

**מה קורה אם לא מתקינים את הטיימר:** הקונסולה **חוסמת** כל שינוי רשת
שיכול לנתק אותה, ואומרת בדיוק למה. שינוי על כרטיס אחר (בלי שער, בלי
DNS ובלי נתיבים) ממשיך לעבוד. הגנה שלא הוכחה אינה הגנה, ולכן היא לא
נחשבת קיימת רק כי הקוד שלה נמצא במאגר.

**דרישה נוספת על המכונה:** ‏`/etc/network/interfaces` חייב להכיל
`source /etc/network/interfaces.d/*`. זו ברירת המחדל של Debian; אם היא
הוסרה, כל מה שנכתב שם הוא קובץ שאיש לא קורא. הקונסולה בודקת ואומרת.

## איך יודעים שהכל תקין — מסך הבריאות

קונסולה → לשונית **בריאות**: רמזור לכל בדיקה, במקום `ss -ulnp` ביד.

| בדיקה | ירוק | אדום |
|---|---|---|
| פורט 67 (DHCP) | dnsmasq מאזין | תהליך זר תפס אותו (בשמו) |
| פורט 69 (TFTP) | dnsmasq מגיש | אף אחד לא מגיש |
| שירות dnsmasq | רץ | נפל, עם המצב |
| קבצי האתחול | shim/GRUB/התפריט על שורש ה-TFTP | מה חסר, בשמו |
| השרת בכתובת ההפצה | `/boot/menu` עונה בכתובת שב-GRUB | לא עונה |
| כרטיסי רשת | מי מחובר ומי מגיש DHCP | אין כרטיסים |

בדיקה שאי אפשר להריץ (למשל על מכונת פיתוח בלי systemd) מוצגת
באפור — "אי אפשר לבדוק כאן", לא אדום מזויף.

## בדיקת קצה ידנית (רשות)

מכל מחשב ברשת, לוודא שה-TFTP עונה:

```bash
tftp <כתובת-השרת> -c get bootx64.efi
```

ומחשב פיזי עם UEFI ו-Secure Boot שמאותחל ב-PXE צריך להגיע לתפריט —
או, בלי משימה, לעלות מהדיסק תוך שניות (הדגמה 3 באפיון).
