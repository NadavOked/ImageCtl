# ‏tools/git — שני שומרים לתהליך

הסקריפטים כאן אינם נוחות. כל אחד מהם נולד מכשל שקרה, ושניהם מממשים את
אותו עיקרון: **פעולה שלא הצליחה לבדוק — נכשלת, לא מוותרת** (עיקרון 5).

---

## ‏`lab-work-checkout.sh` — עץ עבודה על המעבדה שאינו יכול לרשת ref מיושן

```
tools/git/lab-work-checkout.sh <מספר-Issue> [--host root@10.98.10.8] [--key <נתיב>] [--force]
```

יוצר `/root/ic-<N>` ו-`/root/ic-<N>-tmp` על המעבדה, **ומאמת** שה-HEAD
של העץ החדש זהה בדיוק ל-`origin/main` שנמשך זה עתה. אם לא — יציאה
שאינה אפס והודעה שנוקבת בשני ה-sha.

**למה זה לא `git clone` רגיל** (‏#190): ‏`/root/ImageCtl` פרוס לפי tag,
ולכן הוא יושב ב-**HEAD מנותק** — וזה המצב התקין שלו. הענף `main`
**המקומי** שלו אינו זז עם `git fetch`, ויכול לפגר. ‏`git clone --shared`
מעתיק את `refs/heads/*` של המקור אל `refs/remotes/origin/*` של העותק,
ולכן `origin/main` **בעותק** הוא ה-main המיושן.

נמדד ב-2026-08-31, על אותו ריפו ובאותו רגע:

| השיטה | ה-HEAD שהתקבל | קוד יציאה |
|---|---|---|
| `git clone --shared` ואז `git checkout main` | `d5b646f` ❌ | **0** |
| `lab-work-checkout.sh` | `58deb92` ✓ | 0 |

השיטה הנאיבית לא נכשלה. היא **הצליחה, ונתנה עץ שגוי** — ‏8 קומיטים
אחורה, בלי שום סימן.

הסקריפט מוודא גם שה-HEAD של המקור **לא זז** בזמן ה-fetch, כדי שהוא
לא יוריד את השרת הפרוס מהתג שלו.

## ‏`after-merge-check.sh` — כלל 2, "‏PR ירוק אינו main ירוק"

```
tools/git/after-merge-check.sh [<sha>]        # ברירת מחדל: origin/main אחרי fetch
```

מריץ `gh api .../commits/<sha>/check-runs`, ממתין עד שכולן מסתיימות,
ויוצא **0 רק אם כולן `success`**.

**מה שהוא מסרב לקרוא לו הצלחה:**

- בדיקה שנכשלה
- בדיקות שעדיין רצות כשפג הזמן
- שגיאת API
- **אפס בדיקות** — זו המלכודת. "לא מצאתי בדיקות" אינו "הכול עבר"
- אי-התאמה בין `total_count` למה שהוחזר בפועל (יותר מ-100 בדיקות)

בקרה שלילית שהורצה בפועל:

| מה נבדק | תוצאה | יציאה |
|---|---|---|
| ‏`main` ירוק | ‏7 בדיקות, כולן success | 0 |
| ‏`02f2d67` — המיזוג שהסתיר את #177 | `pytest (3.12) failure` | 1 |
| קומיט השורש, בלי בדיקות כלל | "zero check-runs returned" | 1 |
| ‏sha לא תקין | "invalid commit SHA" | 2 |

**הוא עושה `git fetch origin main` לפני שהוא מחליט מיהו main.** בלי זה
הוא היה נשען על ref מעקב מקומי שיכול לפגר — כלומר נופל בדיוק במוקש
של #190, ומדווח "‏main ירוק" על main שאינו main.

**הערה על `skipped`:** כל תוצאה שאינה `success` נחשבת כישלון, כולל
`skipped` ו-`neutral`. זה מכוון — "לא רץ" ו"עבר" הם שני מצבים שונים —
אבל אם ייווסף workflow עם סינון נתיבים, הוא יצבע את הבדיקה אדום. אז
צריך יהיה להכריע, לא להרחיב את ההיתר בשקט.
